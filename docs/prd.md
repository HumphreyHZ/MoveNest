# MoveNest PRD

## 1. 文档说明

MoveNest 是一个面向欧美城市女性的轻量居家训练产品原型。本 PRD 描述产品目标、核心体验、原型范围、关键假设和验证方法。

需要特别说明：当前 Demo 没有接入真实 AI 模型、账号系统或数据服务。所谓“AI 调整”由前端规则、状态变化和解释性文案模拟，用于展示产品体验与交互闭环，不代表已经实现可上线的智能推荐能力。

## 2. 问题与产品目标

目标用户并非不知道运动有益，而是容易在“选择什么、是否适合自己、能否坚持”这些问题上停住。MoveNest 希望降低第一次开始居家训练时的决策压力。

本次 Demo 聚焦一个核心目标：

> 让首次用户在低压力、信息充分的情况下，快速找到并开始一节适合当下状态的短时居家训练。

“60 秒内开始训练”是本项目希望验证的产品假设，不是已经通过用户测试证明的结果。

## 3. 目标用户与使用场景

### 目标用户

- 25-35 岁、生活在欧美城市的女性。
- 工作节奏快，久坐或运动习惯不稳定。
- 倾向在家完成短时训练，空间和器械有限。
- 更关注恢复精力、身体舒适和建立习惯，而非高强度消耗。
- 可能在疲惫、时间不足或轻微身体不适时需要更保守的选择。

### 典型场景

工作日傍晚，用户只有 8-15 分钟，希望活动身体，但不想浏览大量课程，也不确定高强度动作是否适合当前状态。她需要一个明确、容易理解且可以随时降低难度的起点。

## 4. 关键假设

以下内容是待验证假设，不作为既定用户事实：

1. 单一明确推荐比先展示完整课程库更容易促成首次开始。
2. 时长、强度、器械和动作预览能降低用户的不确定感。
3. “疲惫、膝盖不适、只有 8 分钟”等轻量 Check-in 能帮助用户理解个性化价值。
4. 训练中的暂停、跳过和 Too hard 反馈能增强控制感。
5. 非身材焦虑导向的文案更符合低压力 wellness 定位。

## 5. 核心体验链路

`Welcome -> Home -> Workout Detail -> Active Workout -> Completion`

| 页面 | 用户任务 | 产品作用 | 主要操作 |
| --- | --- | --- | --- |
| Welcome | 判断产品是否适合自己 | 建立低压力、可信的第一印象 | Start as Guest |
| Home | 找到今天可以开始的课程 | 提供默认推荐、状态 Check-in 和备选课程 | 选择课程 |
| Workout Detail | 判断课程是否安全、可完成 | 展示时长、强度、目标、动作与低冲击说明 | Start Workout |
| Active Workout | 跟随动作并保持控制感 | 展示计时和教练提示，支持暂停、跳过、Too hard | Complete Workout |
| Completion | 形成完成感并反馈体验 | 收集难度感受，表达下一次计划会参考反馈 | Save tomorrow's plan |

## 6. 当前实现范围

### 已实现

- 游客进入，无注册阻力。
- 一节默认推荐课程和两节备选课程。
- 三项轻量状态 Check-in。
- 根据 Check-in 状态切换解释性文案。
- 课程详情、动作预览和低冲击说明。
- 训练计时、暂停、跳过和 Too hard 反馈提示。
- 完成总结、三档难度反馈和返回首页闭环。

### 能力边界

- Check-in 不会真实重排推荐课程，默认推荐始终固定。
- Too hard 只触发反馈文案，不会真实替换动作或自动缩短训练。
- 完成页反馈只保存在当前 React 会话中，不会写入数据库。
- “Save tomorrow's plan” 返回首页，不会创建真实日程或提醒。
- Demo 没有真实登录、用户档案、推送、支付、课程内容后台或 AI API。

因此，当前版本应表述为“规则驱动的个性化体验原型”，而不是“已完成 AI 个性化推荐系统”。

## 7. 推荐逻辑设想

当前原型只展示解释层。若进入 MVP，推荐逻辑可采用“安全规则优先、模型排序其次”的两层结构：

1. 安全过滤：根据疼痛、动作限制、器械和空间排除明显不适合的课程。
2. 候选排序：根据可用时间、能量、目标、历史完成情况和反馈排序。
3. 推荐解释：明确说明“为什么推荐”，避免只给出黑盒结果。
4. 训练中调整：Too hard 后优先降低动作冲击、缩短时长或增加休息。
5. 反馈学习：将完成情况和难度反馈用于下一次推荐，但允许用户查看和修改偏好。

## 8. 成功指标与事件定义

以下目标值是首轮可用性验证建议，不是当前已经取得的数据。

| 指标 | 事件定义 | 首轮验证目标 |
| --- | --- | --- |
| 开始训练耗时 | 从首次进入 Welcome 到点击 Start Workout | 中位数不超过 60 秒 |
| 推荐课程选择率 | 点击默认推荐课程人数 / 进入 Home 人数 | 用于判断默认推荐是否清晰，不预设强行达标 |
| Start 转化率 | 点击 Start Workout 人数 / 查看详情人数 | 不低于 70% |
| 训练完成率 | 点击 Complete Workout 人数 / 开始训练人数 | 不低于 70% |
| 调整功能发现率 | 能发现 Pause、Skip 或 Too hard 的人数 / 测试人数 | 不低于 80% |
| 完成反馈率 | 选择难度反馈人数 / 完成人数 | 不低于 60% |
| 次日计划意愿 | 点击 Save tomorrow's plan 人数 / 完成人数 | 作为留存意愿代理指标 |

建议埋点事件：

- `welcome_view`
- `guest_start`
- `home_view`
- `checkin_changed`
- `course_selected`
- `workout_detail_view`
- `workout_started`
- `workout_paused`
- `workout_skipped`
- `workout_too_hard`
- `workout_completed`
- `difficulty_feedback_selected`
- `tomorrow_plan_saved`

## 9. 可用性测试方案

在下一轮产品迭代前，建议邀请 3-5 名接近目标画像的用户完成以下任务：

> 你刚结束一天工作，只有约 10 分钟，想在家轻松活动一下。请使用产品找到并开始一节你愿意完成的课程。

记录内容：

- 从进入产品到点击 Start Workout 的时间。
- 用户是否理解默认推荐和 Check-in 的关系。
- 用户是否注意到课程时长、强度和低冲击信息。
- 用户是否能发现暂停、跳过和 Too hard。
- 哪些文案让用户困惑或产生不可信感。
- 完成后是否愿意保存下一次计划，以及原因。

测试结果应单独记录，不应在获得真实数据前把目标值写成已达成结果。

## 10. 健康安全与隐私

### 健康安全

- 产品不提供诊断、治疗或医学建议。
- 用户出现疼痛、眩晕、胸闷或明显不适时，应立即停止运动并寻求专业帮助。
- “膝盖不适”等输入只能用于保守筛选，不能用于判断伤病程度。
- 信息不足或风险不明确时，应推荐更低冲击方案，或提示用户咨询专业人士。
- 正式产品中的动作内容应由具备资质的运动或健康专业人员审核。

### 数据与隐私

- 当前 Demo 不上传或持久化任何健康信息。
- 正式产品应说明收集目的、保存期限、删除方式和是否用于模型训练。
- 健康相关信息应遵循数据最小化原则，不应用于无关营销。
- 用户应能修改或删除状态与反馈，并能拒绝个性化处理。

## 11. 后续优先级

### P0：验证核心假设

- 完成 3-5 人可用性测试。
- 让 Check-in 真正改变推荐课程。
- 让 Too hard 真实调整下一动作或时长。
- 增加基础事件埋点。

### P1：形成连续体验

- 保存训练记录和用户偏好。
- 根据历史反馈生成次日计划。
- 增加安全筛查和内容审核机制。

### 暂不进入本次 Demo

- 社区、排行榜和挑战体系。
- 复杂会员与支付功能。
- 大规模课程商城。
- 医疗诊断或康复治疗建议。
