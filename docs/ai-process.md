# AI Process

## 我如何使用 AI 从 PRD 到 Demo

我把 AI 当作产品设计和前端实现的协作工具，而不是完全替代判断的生成器。流程上先用 AI 拆解题目，明确目标用户、核心链路和 Demo 边界；再让 AI 产出低保真页面结构、英文文案和 React 组件方案；最后根据笔试场景人工收敛范围，避免功能过多、视觉过度模板化或训练建议不安全。

在实现阶段，AI 输出了 Vite + React + Tailwind 的基础代码结构、页面组件拆分、静态数据组织方式和交互状态设计。我直接采用了单页 state 控制流程、五页核心链路、今日推荐卡片、训练中 Too hard 反馈提示、完成页三档反馈等部分。

人工修改的部分主要有三类。第一是产品判断：保留 1 分钟内完成课程选择的主链路，不扩展真实登录、课程库、用户画像问卷和会员功能。第二是文案判断：删除焦虑型、减脂导向或过度承诺的表达，改为更自然的英文 wellness 语气。第三是安全判断：动作只选择 Gentle Warm-up、Chair Squat、Wall Push-up、Standing Core、Cool-down Stretch 这类低冲击动作，并避免给出医学化承诺。

## Prompt 示例

### Prompt 1：从题目拆产品链路

```text
你是一名 AI x 运动健康产品经理。请基于“面向欧美城市女性用户的居家训练 App”笔试题，帮我拆出一个 5 页面移动端 Demo 的核心用户链路。目标用户是 25-35 岁、工作忙、没有固定健身习惯、希望在家做低压力短时训练的欧洲城市女性。请重点说明每个页面的目标、用户心理、核心信息和主按钮，不要扩展登录、社区、会员等非核心功能。
```

### Prompt 2：生成英文产品文案

```text
请为一个名为 MoveNest 的 gentle home workout app 写英文 UI 文案。品牌定位是 calm, clean, premium, European wellness。不要使用减肥羞辱、焦虑驱动、强刺激健身房风格文案。页面包括 Welcome、Home 今日推荐、Workout Detail、Active Workout 和 Completion。文案需要自然、简洁，适合 25-35 岁欧美城市女性第一次打开 App。
```

### Prompt 3：生成前端实现方案

```text
请用 React + Vite + Tailwind CSS 设计一个无后端移动端 Web App 原型。不要使用 router，用 React state 控制页面切换。页面包括 Welcome、Home、Workout Detail、Active Workout、Completion。要求组件化、静态数据集中管理、所有按钮有 hover 和 active 状态、整体居中模拟手机端。视觉风格是 warm ivory / sage / soft coral / ink，不依赖外部图片。
```

### Prompt 4：检查 Demo 是否过度复杂

```text
请从产品经理笔试评分角度审查这个 Demo 范围：是否能体现 AI 个性化推荐和训练反馈闭环？是否有不必要的功能？是否能在 1 分钟内走通核心路径？请指出应该删除、保留和强化的部分，优先保证 Demo 清晰、可信、可讲述。
```

## 我如何判断 AI 输出是否可信

第一，看用户场景是否一致。AI 如果建议复杂问卷、账号体系、课程商城或社交挑战，我会判断为偏离首次打开核心流程，因为目标是快速找到第一节适合自己的训练。

第二，看文案自然度。英文文案需要像真实欧美 wellness 产品，而不是直译中文或夸张营销语。我会删除类似 burn fat fast、transform your body、no excuses 这类焦虑或羞辱感表达。

第三，看训练动作安全性。AI 可能生成跳跃、波比跳、深蹲跳等高冲击动作，但目标用户是新手且可能有膝盖不适，所以我只保留低冲击、可在公寓完成、容易理解的动作，并避免医疗建议。

第四，看视觉是否模板化。AI 常输出普通卡片堆叠或黑红健身风，我会用更克制的颜色、留白、圆形计时视觉和柔和状态反馈，让产品更接近女性健康生活方式品牌。

第五，看功能是否过度复杂。真实 AI API、完整训练计划、账号登录和课程库都可以成为未来版本，但在笔试 Demo 中会分散注意力。本次只保留能证明“推荐-开始-调整-完成-反馈”闭环的功能。
